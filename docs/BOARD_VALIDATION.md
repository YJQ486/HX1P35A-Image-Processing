# 板级测试：怎样记录真实开发板上的结果

板级测试就是在真实摄像头、开发板和显示器上观察。它回答“现场是否正常”，与电脑仿真分开记录。

## 已有观察

|时间或阶段|开发者反馈|能说明什么|仍未确认|
|---|---|---|---|
|2026-10-16，C 白平衡|效果与 A 接近，可能略有改善|C 已有实物观察|偏色仍在，现场文件指纹和持续时长未核验|
|后续 Logo 候选|上板成功|Logo 版本已有现场反馈|完整逐项验收、加载 SHA 和长稳记录|
|原红色检测|中央基本能框住，靠边会突然扩框|原算法存在实际稳定性问题，短视频约 31.28 秒|不能据此认定连续 20 分钟通过|
|2026-10-18，修复版 `stable`|已上板，见[亮度核查](SC520CS_BRIGHTNESS_BASELINE_AUDIT.md)|修复候选已收到上板反馈|实际加载 SHA、框选改善、当前模式/分支和长时间表现|

上板反馈不等于读出了板内文件指纹；本地 bit 的 SHA256 与现场实际选择文件需要分别确认。

## 建议先做这一轮记录

固定灯光、摄像头位置和显示器设置，记录正在使用的文件名、SHA256 和白平衡分支。若无法核实文件指纹，明确写“未确认”。再按顺序操作：

1. 拍摄完整画面，检查摄像头输出、右上 Logo 和左上状态面板。
2. 短按走完彩色、灰度、二值化、轮廓、彩色；长按走完 A/B/C，每档至少等待 20 帧，建议 3 秒。
3. 红纸从中央移向四边和角落，部分移出再返回；加一个远处小红点，观察是否把框拉大。记录误框、漏框和延迟。
4. 移走红纸、放入另一块红区，观察旧框消失与目标取舍。修复版允许短暂保留旧框，具体按[修复报告](SC520CS_RED_STABILITY_REPORT.md)的完整帧规则判断。
5. 有框时复位，确认视频恢复且旧框不沿用；复位后默认彩色/A，演示 C 时需重新选择。
6. 连续观察 20～30 分钟，记录开始、结束、异常时间和次数，保留原始视频或带时间的分段记录。

|记录项|填写内容|
|---|---|
|文件与硬件|文件名、SHA256 或未确认；板卡、摄像头、供电、显示器|
|条件|灯光、摄像头位置、显示模式、A/B/C 分支|
|时间|开始、结束、总时长|
|现象|黑屏、花屏、滚屏、停住、漏框、误框；没有异常也记录观察范围|
|操作|切换与复位次数、每次结果|
|证据|原始视频、照片或现场记录路径|
|结论|通过/失败/未完成，以及未覆盖的项目|

当前长时间稳定性和最终验收仍为 `not tested`。Flash 固化与脱离电脑的断电启动是另一项测试；按复位键恢复不能代替它。下面保留 AWB 阶段的详细观察与原测试表，尚未填写的内容不当作已完成。

|记录项|待填写内容|
|---|---|
|镜像对应|实际已加载文件名/SHA；若无法核实，明确“加载 SHA 未确认”|
|环境|板卡、摄像头、供电、显示器及当前室内照明|
|时间|开始、结束、总时长（目标20～30分钟）|
|连续输出|黑屏、花屏、滚屏、卡死、异常帧/丢帧现象，各记录时间与次数；没有计数器时只写观察结果|

|证据|连续视频或带时间的分段记录、开始/结束照片、异常原始片段路径|
