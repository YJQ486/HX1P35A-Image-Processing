# 术语与指标说明

这份表用于读懂项目文档。代码中的信号名、文件名和工具输出保留原名，方便找到实际实现。

## 画面与处理

|术语|通俗解释|在本项目中用来做什么|
|---|---|---|
|FPGA / RTL / Verilog|FPGA 是可配置数字电路芯片；RTL 是描述寄存器与数据运算关系的设计；Verilog 是使用的语言|搭建持续接收、处理和输出像素的电路|
|像素 / 帧|像素是一个画面点；帧是一整幅画面|一帧有 1280×720 个有效像素|
|MIPI / CSI / D-PHY|摄像头高速传输接口及其协议、物理层|把摄像头原始数据送入 FPGA|
|lane / RAW10|lane 是传输通道；RAW10 是每个原始像素用 10 位表示|摄像头使用两条数据通道；这不是 10 位完整 RGB 颜色|
|ISP / demosaic|图像处理环节；demosaic 将传感器的颜色采样还原为 RGB|得到能继续处理和显示的彩色数据|
|RGB888 / 四像素每拍|红、绿、蓝各用 8 位；每个时钟周期同时处理四个像素|一次处理 96 位颜色数据，提高处理能力|
|AE / 曝光 / 增益|AE 是自动曝光；曝光决定采光时间，增益放大信号|让画面明暗接近目标，受上限和控制状态限制|
|AWB / 单位增益|AWB 是自动白平衡；单位增益指乘以 1|调整颜色比例，或用 B 分支作对照|
|灰度 / 二值化 / Sobel|只有明暗；只留黑白；突出明暗变化形成轮廓|四种显示效果中的三种|
|OSD / alpha|OSD 是在视频上加字或图；alpha 决定用图案还是透出底图|显示状态、Logo 和检测结果|
|BLC / gamma / CFA|黑电平校正；亮度曲线变换；传感器的颜色滤光排列|核查画质链路时使用；源码有模块不代表已接入|
|VTS|传感器每帧的总行数配置，包括非有效画面部分|与曝光允许范围有关；不能直接当作画面有效高度|

## 数据顺序与同步

|术语|通俗解释|为什么需要关心|
|---|---|---|
|时钟 / 一拍|电路按周期推进；一拍是一个时钟周期|数据和“这一点属于哪行哪帧”的标记必须同步|
|SOF / EOL / valid|一帧开始 / 一行结束 / 当前数据有效|标记错位可能导致漏掉模式切换或错放像素|
|DE / HS / VS|有效画面标记 / 行同步 / 帧同步|显示端据此确定每个像素的位置|
|流水线 / 寄存级|把计算分成几步，用寄存器保存中间结果|缩短每一步计算时间；对应标记也要延迟相同拍数|
|96→128 打包|把每组 12 字节重排成每组 16 字节|适应后面的存储接口；本身不是亮度缩放|
|FIFO / DDR|按先后顺序暂存的小队列 / 存整帧的大容量存储|协调摄像头写入和显示读取的节奏|
|反压|下游暂时接不下数据，要求上游等待|链路若不能等待，需要单独检查溢出和恢复|
|CDC / 时钟域|不同节奏的电路之间传信息 / 使用同一时钟的一组电路|直接传递可能得到不完整或不稳定的数据|
|mailbox / req / ack|保存一份完整数据，再发请求、等待确认的传递方法|让坐标和状态成组传到另一时钟域|
|原子更新 / 相干|一组坐标同时换成新值 / 各字段属于同一份结果|防止把新左边界和旧右边界拼成错误框|
|Gray / MTBF|相邻值仅变一位的编码 / 平均故障间隔估算|Gray 常用于跨域指针；时序通过不能替代可靠性估算|
|PLL / PHY|产生所需时钟的电路 / 高速接口底层电路|部分行为依赖专用硬件，模块仿真不能完整覆盖|

## 构建、证据与数值

|术语|通俗解释|怎样读报告|
|---|---|---|
|仿真 / 自检 / 回归|给电路模型输入测试数据 / 自动比较结果 / 改动后重跑原测试|只能支持覆盖到的输入、模型和功能|
|force / 数值模型|测试中人为设置信号 / 用等价数学计算替代部分电路|帮助隔离测试；不能算作完整硬件链路实测|
|综合 / 布局布线 / 网表|把代码转成电路 / 安排电路位置与连线 / 转换后的连接清单|共同决定实际实现和时序|
|clean 综合|从源码重新综合|不表示零告警，也不表示实际运行通过|
|bit / bitgen / checked bitgen|FPGA 配置文件 / 生成文件 / 本项目在约束复核后生成文件的流程|生成成功不等于已加载或已验收|
|SRAM 加载 / Flash 固化 / 冷启动|临时配置 / 存入非易失存储 / 断电后重新启动|临时显示正常不证明脱离电脑也能独立启动|
|SHA256 / 源绑定|文件内容的指纹 / 把测试、源码、构建产物对应起来|文件名相同不代表内容相同；本地指纹不识别板内实际文件|
|SDC / ADC|时序要求文件 / 引脚约束文件|它们规定要检查的时间要求和实际管脚|
|Setup / Hold|数据在采样前要提前稳定 / 采样后还需保持稳定|两者都需要检查|
|WNS / slack|最差路径还剩多少时间余量|负数表示该检查有违例；正数只说明已检查范围有余量|
|TNS|所有负时间余量的总和|0 表示该报告中没有累计负余量，不代表所有物理路径都已覆盖|
|时序覆盖率|工具按其统计口径已覆盖的检查比例|98.95% 不表示真实运行成功率为 98.95%|
|LUT / REG / Slice|组合逻辑查找表 / 寄存器 / 器件逻辑单元|资源占用；综合与布线报告可能口径不同|
|ERAM / DSP|片上存储块 / 专用乘加等运算块|分别承担缓存和算术运算|
|NACK / group hold|器件未确认总线事务 / 暂存一组寄存器更新再统一提交|请求发出、事务完成、读回和图像生效应分开记录|

例如 `setup WNS=+0.100 ns`，表示已建模的最差建立时间检查还有 0.100 纳秒余量。它不是图像延迟，也不是“每运行一秒出错的概率”。`checks=4615435, errors=0` 表示这次仿真的 4,615,435 项比较没有报错，不能直接换算为真实环境覆盖率。
