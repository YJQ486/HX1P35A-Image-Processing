# 术语与指标说明

本页解释视频通路、时钟域和验证报告中常见的术语。查阅时可结合“工程用途”或“判定范围”理解它在本项目中的作用；代码、文件名和工具输出沿用原名。

## 像素、接口与图像处理

|术语|定义|工程用途|
|---|---|---|
|FPGA / RTL / Verilog|FPGA：现场可编程门阵列；RTL：寄存器传输级描述；Verilog：硬件描述语言|实现实时像素接收、处理与输出|
|像素 / 帧|像素为图像基本采样单元；帧为一幅完整图像|一帧有 1280×720 个有效像素|
|MIPI / CSI / D-PHY|摄像头高速传输接口及其协议、物理层|接收摄像头原始像素流|
|lane / RAW10|lane 是传输通道；RAW10 是每个原始像素用 10 位表示|摄像头使用两条数据通道；RAW10 位宽不表示完整 RGB 颜色的通道位宽|
|ISP / demosaic|ISP：图像信号处理；demosaic：去马赛克，将颜色滤波阵列采样还原为 RGB|生成后续处理与显示所需的彩色数据|
|RGB888 / 四像素每拍|红、绿、蓝各用 8 位；每个时钟周期同时处理四个像素|一次处理 96 位颜色数据，提高处理能力|
|AE / 曝光 / 增益|AE：自动曝光；曝光控制积分时间，增益调节信号放大倍数|根据亮度统计调节曝光与增益，受限幅及控制状态约束|
|AWB / 单位增益|AWB：自动白平衡；单位增益为乘法系数 1|调整颜色比例，或用 B 分支作对照|
|灰度 / 二值化 / Sobel 边缘检测|按亮度编码；按阈值输出两级值；计算亮度梯度以提取边缘|四种显示效果中的三种|
|OSD / alpha|OSD：屏幕信息叠加；alpha 为图案透明或混合控制值|显示状态、Logo 和检测结果|
|BLC / gamma / CFA|黑电平校正；亮度曲线变换；传感器的颜色滤光排列|核查画质链路时使用；源码有模块不代表已接入|
|VTS|传感器每帧的总行数配置，包括非有效画面部分|与曝光允许范围有关；不能直接当作画面有效高度|

## 行帧时序与跨时钟域通信

|术语|定义|接口影响|
|---|---|---|
|时钟 / 一拍|时钟提供同步采样基准；一拍表示一个时钟周期|像素数据与行帧标记须保持时序对齐|
|SOF / EOL / valid|SOF：帧首标记；EOL：行尾标记；valid：数据有效标记|标记错位可能导致模式请求漏采或像素位置错误|
|DE / HS / VS|有效画面标记 / 行同步 / 帧同步|显示端据此确定每个像素的位置|
|流水线 / 寄存级|以寄存器划分组合计算阶段并保存中间结果|缩短每一步计算时间；对应标记也要延迟相同拍数|
|96→128 打包|将连续 12 字节输入组重排为连续 16 字节输出组|匹配后级存储接口，不改变像素亮度比例|
|FIFO / DDR|FIFO：先进先出队列；DDR：本工程用于整帧缓存的存储接口及存储资源|协调摄像头写入和显示读取的节奏|
|反压|下游暂停接收时向上游传递的流控请求|链路若不能等待，需要单独检查溢出和恢复|
|CDC / 时钟域|CDC：跨时钟域通信；时钟域：由同一时钟驱动的逻辑范围|直接传递可能得到不完整或不稳定的数据|
|mailbox / req / ack|mailbox：保持成组数据的跨域握手机制；req/ack：请求/应答|将坐标和状态一致地传递至目的时钟域|
|原子更新 / 相干|一组坐标同时换成新值 / 各字段属于同一份结果|避免不同版本的边界坐标混合|
|Gray / MTBF|相邻值仅变一位的编码 / 平均故障间隔估算|Gray 常用于跨域指针；时序通过不能替代可靠性估算|
|PLL / PHY|产生所需时钟的电路 / 高速接口底层电路|部分行为依赖专用硬件，模块仿真不能完整覆盖|

## 构建步骤与验证指标

|术语|定义|判定范围|
|---|---|---|
|仿真 / 自检 / 回归|仿真：对电路模型施加输入；自检：自动比较期望与实际结果；回归：修改后重新执行既有测试|只能支持覆盖到的输入、模型和功能|
|force / 数值模型|测试中人为设置信号 / 用等价数学计算替代部分电路|帮助隔离测试；不能算作完整硬件链路实测|
|综合 / 布局布线 / 网表|综合：转换 RTL 为逻辑网表；布局布线：映射物理位置与互连；网表：电路连接描述|共同决定实际实现和时序|
|clean 综合|从源码重新综合|不表示零告警，也不表示实际运行通过|
|bitstream / bitgen / checked bitgen|FPGA 配置文件 / 生成文件 / 本项目在约束复核后生成文件的流程|生成成功不等于已加载或已验收|
|SRAM 加载 / Flash 固化 / 冷启动|临时配置 / 存入非易失存储 / 断电后重新启动|临时显示正常不证明脱离电脑也能独立启动|
|SHA-256 / 源绑定|SHA-256：文件内容摘要；源绑定：建立测试、源码与构建产物的对应关系|文件名相同不代表内容相同；本地指纹不识别板内实际文件|
|SDC / ADC|时序要求文件 / 引脚约束文件|它们规定要检查的时间要求和实际管脚|
|Setup / Hold|数据在采样前要提前稳定 / 采样后还需保持稳定|两者都需要检查|
|WNS / slack|WNS 为最差负时序裕量指标；slack 为路径时间裕量|负数表示该检查有违例；正数只说明已检查范围有余量|
|TNS|所有负时间余量的总和|0 表示该报告中没有累计负余量，不代表所有物理路径都已覆盖|
|时序覆盖率|工具按其统计口径已覆盖的检查比例|98.95% 不表示真实运行成功率为 98.95%|
|LUT / REG / Slice|组合逻辑查找表 / 寄存器 / 器件逻辑单元|资源占用；综合与布线报告可能口径不同|
|ERAM / DSP|片上存储块 / 专用乘加等运算块|分别承担缓存和算术运算|
|NACK / group hold|器件未确认总线事务 / 暂存一组寄存器更新再统一提交|请求发出、事务完成、读回和图像生效应分开记录|

阅读结果时，先区分时间余量、比较次数和覆盖率。例如，`setup WNS=+0.100 ns` 表示已建模的最差建立时间检查有 0.100 纳秒余量；它不能用于计算图像延迟或故障概率。`checks=4615435, errors=0` 表示该次仿真完成 4,615,435 项比较且未报错，真实环境覆盖程度仍由测试场景与模型决定。
